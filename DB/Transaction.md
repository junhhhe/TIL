# 💡 Transaction (트랜잭션) 이란?

트랜잭션(Transaction)은 데이터베이스의 상태를 변화시키기 위해 수행하는 **작업의 단위**
쉽게 말해, 데이터베이스에서 행해지는 일련의 연산들을 하나로 묶어 처리하는 논리적인 작업 덩어리

트랜잭션은 모두 성공하거나 (**Commit**), 모두 실패하여 원래 상태로 되돌려야 (**Rollback**)함, 이 특징을 통해 데이터베이스의 **일관성**과 **무결성**을 보장

---

## 🏗️ 트랜잭션의 주요 연산

트랜잭션의 두 가지의 주요 연산

* **Commit (커밋):**
    * 하나의 트랜잭션이 성공적으로 완료되었음을 데이터베이스에 알리는 연산
    * 커밋 연산이 수행되면, 트랜잭션이 수행한 변경 내용이 **영구적으로** 데이터베이스에 반영
* **Rollback (롤백):**
    * 트랜잭션 처리에 오류가 발생했거나, 사용자에 의해 취소되어 트랜잭션이 정상적으로 완료되지 못했을 때 실행하는 연산
    * 롤백 연산이 수행되면, 해당 트랜잭션이 데이터베이스에 적용했던 변경 내용들이 **취소**되고, 트랜잭션 시작 전의 **원래 상태**로 되돌아감

---

## 🔒 트랜잭션의 특징: ACID

성공적인 트랜잭션은 반드시 다음 네 가지 특성을 만족해야 하며, 이를 **ACID 특성**이라고 부름

| 특성 (Property) | 의미 (Meaning) | 설명 (Explanation) |
| :--- | :--- | :--- |
| **A**tomicity (원자성) | **All or Nothing** | 트랜잭션 내의 모든 연산은 **모두 성공**하거나, 아니면 **모두 실패**하여 **어떤 것도 반영되지 않아야** 합니다. (Commit 또는 Rollback) |
| **C**onsistency (일관성) | **Valid State** | 트랜잭션이 실행을 성공적으로 완료하면 언제나 **일관성 있는 상태**로 데이터베이스를 변환해야 합니다. 즉, 트랜잭션은 데이터베이스의 제약 조건이나 규칙을 위반하지 않아야 합니다. |
| **I**solation (격리성) | **Separateness** | 동시에 실행되는 트랜잭션들은 서로 **간섭할 수 없으며**, 각 트랜잭션은 마치 **혼자 실행되는 것처럼** 독립적으로 동작해야 합니다. |
| **D**urability (영속성) | **Persistence** | 성공적으로 완료된(Commit된) 트랜잭션의 결과는 시스템 오류가 발생하더라도 **영구적으로** 데이터베이스에 반영되어야 합니다. |

---

## 🏦 트랜잭션의 예시 (은행 계좌 이체)

1.  **A 계좌에서 10만 원 인출** (데이터베이스 변경 1)
2.  **B 계좌로 10만 원 입금** (데이터베이스 변경 2)

이 두 작업은 **하나의 트랜잭션**으로 묶여야 함

* 만약 1번은 성공하고 2번이 실패하면, A는 돈을 잃고 B는 돈을 받지 못하는 **일관성 없는 상태**가 됨
* 따라서, 1번과 2번 중 하나라도 실패하면 전체 트랜잭션을 **Rollback**하여 A 계좌에 다시 10만 원을 돌려놓아 **원자성**을 보장
* 두 작업이 모두 성공했을 때만 **Commit**하여 최종적으로 반영
