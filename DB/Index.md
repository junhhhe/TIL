## 📚 인덱스(Index)

---

### 1. 인덱스(Index)란?

데이터베이스 인덱스는 **추가적인 쓰기 작업과 저장 공간을 활용**하여 데이터베이스 테이블에 저장된 데이터의 **검색 속도를 향상시키기 위한 자료구조**

* 책에서 원하는 내용을 찾을 때 목차나 색인을 이용하는 것과 같은 원리
* 인덱스를 사용하면 전체 테이블을 스캔하는 대신, 인덱스를 이용해 검색 대상 레코드의 범위를 좁혀 데이터 검색 속도를 크게 향상시킬 수 있음.
* 특정 컬럼(열) 또는 컬럼들의 조합에 대한 값과 해당 값이 저장된 레코드(행)의 위치를 매핑

---

### 2. 인덱스의 장점과 단점

| 구분 | 장점 | 단점 |
| :--- | :--- | :--- |
| **성능** | 1. 검색 대상 레코드 범위를 줄여 **검색 속도 향상** | 1. **INSERT/UPDATE/DELETE** 작업 시 인덱스를 함께 업데이트해야 하므로 **성능 저하(오버헤드) 발생** |
| | 2. `ORDER BY`, `GROUP BY`, `WHERE` 절 등이 사용되는 작업 효율성 증대 | 2. 한 페이지를 동시에 수정할 수 있는 **병행성(Concurrency) 감소** |
| **데이터 관리** | 3. 중복 데이터를 방지하거나 특정 컬럼의 **유일성(Unique) 보장** | 3. 인덱스 생성에 따른 **추가적인 저장 공간 필요** |
| | | 4. 인덱스 생성에 시간이 오래 걸릴 수 있음 |

---

### 3. 인덱스의 자료구조

#### 1) B-Tree (B-트리)
* 데이터베이스에서 **가장 널리 사용**되는 인덱스 자료구조
* 시간 복잡도: **O(logN)**
* 균형 잡힌 이진 검색 트리(Balanced Binary Search Tree)이며, 각 노드 내의 데이터는 항상 정렬된 상태를 유지
* 노드 내에 여러 개의 키와 해당 키에 해당하는 데이터가 함께 저장

#### 2) B+Tree (B+트리)
* B-Tree의 변형된 구조로, B-Tree보다 더 많은 키를 가질 수 있음
* 내부 노드(Internal node)와 단말 노드(Leaf node)로 구분
    * 내부 노드: 검색을 위한 인덱스만 저장
    * 단말 노드: **모든 데이터가 저장**
* 모든 리프 노드가 연결 리스트(Linked List)로 연결되어 있어, 범위 검색(Range Search)이나 순차 검색(Sequential Search)에 특히 효율적

#### 3) Hash Table (해시 테이블)
* 시간 복잡도: O(1)로 매우 빠른 검색이 가능
* 키(Key)를 해시 함수로 변환한 후 해당 해시 값의 위치를 찾아 검색
* **등호(=) 연산에만 특화**되어 있어, 부등호 연산(`>`, `<`)이 자주 사용되는 데이터베이스 검색에는 적합하지 않음

---

### 4. 인덱스를 사용해야 하는 경우

1.  **대량의 데이터를 검색하는 경우**: 전체 스캔을 대체하여 부하를 줄이고 검색 속도를 향상
2.  **정렬된 결과를 출력하는 경우**: 인덱스를 사용하면 정렬된 결과를 매우 빠르게 출력
3.  **조인(JOIN) 연산을 수행하는 경우**: 조인 대상 테이블의 데이터를 빠르게 검색하여 연산 속도를 향상
4.  **유니크(Unique)한 값을 가져오는 경우**: 유니크한 값을 가진 필드에 대해 중복되지 않는 값을 빠르게 검색
5.  **검색 빈도가 높은 경우**: 자주 검색되는 필드에 인덱스를 생성하여 검색 속도를 개선
