# 📚 AWS VPC (Virtual Private Cloud)

사용자의 AWS 계정 전용으로 격리된 가상 네트워크 공간

---

## 1. VPC 기본 구조 및 CIDR (영역 정의)

### 1.1. VPC와 리전/AZ의 관계

* **VPC (Virtual Private Cloud):** 리전(Region) 범위에서 생성되는 논리적인 네트워크 공간
* **서브넷 (Subnet):** VPC를 다시 분할한 작은 단위로, 반드시 특정 **가용 영역(Availability Zone, AZ)** 내에 존재해야 함. 리소스(EC2, RDS 등)는 이 서브넷 내에 배치

### 1.2. CIDR (Classless Inter-Domain Routing)

* **역할:** VPC와 서브넷의 IP 주소 범위를 정의 (예: `10.0.0.0/16`)
* **VPC CIDR:** 전체 사설 네트워크의 크기를 결정 (예: `/16`은 65,536개의 IP 주소를 사용 가능)
* **서브넷 CIDR:** VPC CIDR 내에서 서브넷이 사용할 IP 범위를 지정 (예: `10.0.1.0/24`)
* **예약된 IP:** 모든 서브넷은 네트워크 주소, 브로드캐스트 주소 등으로 인해 5개의 IP 주소를 AWS가 예약하여 사용할 수 없음

## 2. 서브넷의 종류와 트래픽 흐름

서브넷은 **라우팅 테이블(Routing Table)** 설정에 따라 Public 또는 Private으로 구분

### 2.1. Public Subnet (공개 서브넷)

* **정의:** 인터넷 게이트웨이(IGW)로 통하는 경로가 라우팅 테이블에 명시되어 있어, 외부 인터넷으로부터 **인바운드/아웃바운드** 통신이 가능한 서브넷
* **배치 리소스:** 웹 서버, 로드 밸런서, Bastion Host 등 외부 노출이 필요한 서비스

### 2.2. Private Subnet (프라이빗 서브넷)

* **정의:** IGW로 직접 통하는 경로가 없어, 외부에서 직접 접근할 수 없는 안전한 서브넷.
* **배치 리소스:** 데이터베이스(RDS), 애플리케이션 서버 등 민감한 데이터나 로직을 처리하는 서비스.

---

## 3. 네트워킹 핵심 구성 요소

### 3.1. 인터넷 게이트웨이 (IGW)

* **역할:** VPC가 외부 인터넷과 통신할 수 있도록 연결하는 논리적 게이트웨이. Public Subnet의 트래픽을 처리
* **특징:** 고가용성을 가지며, 수평적으로 확장되므로 별도의 관리 없이 안정적인 통신을 제공

### 3.2. 라우팅 테이블 (Routing Table)

* **역할:** 서브넷에 연결되어 트래픽의 목적지(Destination)에 따라 패킷을 어디(Target)로 보낼지 결정하는 규칙들의 집합
* **규칙 예시:**
    * **로컬 (Local):** VPC 내부 통신 (`10.0.0.0/16` 등)
    * **인터넷:** 외부 통신 (`0.0.0.0/0` → IGW)
    * **NAT:** Private Subnet의 아웃바운드 통신 (`0.0.0.0/0` → NAT Gateway)

### 3.3. NAT Gateway (Network Address Translation Gateway)

* **역할:** Private Subnet 내의 리소스들이 외부 인터넷으로 **아웃바운드(Outbound)** 접근하는 것을 허용 (업데이트, 외부 API 호출 등)
* **위치:** 반드시 **Public Subnet**에 위치하며, Elastic IP(EIP)를 할당받아 프라이빗 IP를 퍼블릭 IP로 변환하여 통신

## 4. VPC 보안 계층: SG vs NACL

네트워크 보안은 2단계의 필터링을 거침

| 특징 | Security Group (SG) | Network ACL (NACL) |
| :--- | :--- | :--- |
| **적용 범위** | 인스턴스(EC2) 레벨 | 서브넷 레벨 |
| **작동 방식** | **Stateful (상태 저장):** 인바운드를 허용하면, 응답 트래픽(아웃바운드)은 자동으로 허용됨. | **Stateless (비상태 저장):** 인바운드와 아웃바운드 규칙을 모두 명시적으로 허용해야 함. |
| **규칙 특징** | `Allow` (허용) 규칙만 가능 | `Allow`와 `Deny` (거부) 규칙 모두 가능 |
| **평가 순서** | 모든 규칙을 평가함. | 규칙 번호 순서(낮은 번호 우선)로 평가하여, 일치하는 규칙 발견 시 즉시 적용. |

**실제 적용:** SG는 인스턴스별 접속 포트 제어에 주로 사용하며, NACL은 서브넷 전체에 대한 광역적인 보안 정책 (IP 대역 차단 등)에 사용됨

## 5. VPC 설계 체크리스트

| 항목 | 목적 | 확인 사항 |
| :--- | :--- | :--- |
| **고가용성** | 단일 장애점(SPOF) 방지 | Public/Private 서브넷이 최소 2개 이상의 AZ에 분산되어 있는가? |
| **인터넷 접근** | 외부 통신 가능성 | Public Subnet은 IGW로, Private Subnet은 NAT Gateway로 라우팅되는가? |
| **최소 권한** | 보안 강화 | SG와 NACL이 필요한 포트와 IP만 허용하도록 구성되었는가? |
